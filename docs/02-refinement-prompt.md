## Known non-obvious facts — do NOT re-derive, do NOT break

These were established the hard way. Violating any of them reintroduces a crash or a silent failure:

- **`advance(t)` takes SECONDS, not milliseconds** under `frameloop="never"`. R3F computes `delta = timestamp - clock.elapsedTime` and `elapsedTime` is in seconds.
- **All per-frame R3F mutation goes through refs to rendered objects**, never through the `useMemo` binding. The React Compiler ESLint rule (`react-hooks/immutability`) rejects mutating memoised values, and it is right to. Pattern in use: `<primitive object={material} attach="material" ref={materialRef} />`, then mutate `materialRef.current`.
- **The SplitText target MUST stay opaque to React reconciliation.** `RevealText` renders it via `dangerouslySetInnerHTML` and keeps markup identical in reduced and full motion. Reverting that causes `NotFoundError: Failed to execute 'removeChild'` and takes the entire tree down.
- **No raw `<script>` in the React tree** — React 19 does not execute component-rendered inline scripts, and `next/script` `beforeInteractive` does not avoid it. Reduced-motion default is expressed in pure CSS in `tokens.css`; keep it there.
- **Client-only content must be gated behind `useIsHydrated()`** or it produces a hydration mismatch.
- **R3F's `<line>` collides with the SVG `<line>` intrinsic** in TS. `DataScene` constructs `THREE.Line` directly and mounts via `<primitive>`.
- **A fully polymorphic `as` prop collapses props (and ref types) to `never`.** `Reveal` uses a string-union tag plus an explicit JSX switch. Do not "simplify" it back to `createElement`.
- **A dev-only bridge exists**: `window.__knp` = `{ lenis, gsap, ScrollTrigger, scrollState, tick }`, exposed from `ScrollProvider`, stripped from production builds.

## Environment limits — verification honesty is mandatory

**The in-app browser pane does not composite.** Confirmed in the previous phase:

- `requestAnimationFrame` fires **0 times**
- therefore `ResizeObserver` and `IntersectionObserver` never fire
- `focus`/`focusin` events **never fire** (the document is never focused), although `document.activeElement` does update
- screenshots time out
- No real Chrome/Edge is connected, so **cross-browser testing is not possible here**

Workarounds that DO work, and which you should use:

- pump the clock manually: `window.__knp.tick(t)` with `t` in **seconds**, incrementing ~16.67ms per frame
- force measurement: `window.dispatchEvent(new Event('resize'))`
- trigger focus handlers: `el.dispatchEvent(new FocusEvent('focusin', { bubbles: true }))`
- to verify scenes mount, temporarily force `useInView` to return `true`, then **revert it**
- drive scroll: `window.__knp.lenis.scrollTo(...)` then pump

**This means you cannot see or feel anything.** Typography rhythm, transition pacing, scroll weight and "does this look premium" are the core of this phase and are **not observable to you here**.

Therefore:

- Make timing, spacing and typographic changes on **reasoned design judgement**, and state the reasoning in your report.
- **NEVER claim you verified smoothness, pacing, visual quality, or 60fps.** Report precisely what you checked and how.
- Do not chase phantom bugs caused by the dead frame lifecycle. If scroll, view mounting, canvas sizing or animation appear broken, first assume the environment.
- Report cross-browser testing as **not performed**, with the reason. Do not fabricate it.

# THE REFINEMENT WORK

## 1. Audit first

Inspect before modifying: app architecture · component structure · animation system · WebGL system · data files · responsive styles · accessibility · performance · project presentation · Skills Arsenal · CV · Hire Me · Footer.

Produce a short internal list of *actual* problems. Fix those. Leave everything else alone.

## 2. Typography

Audit across the whole site: hierarchy · line lengths · letter spacing · font weights · section spacing · heading scale · mobile typography · transition typography · metadata typography.

Typography must feel intentional. Large text needs room to breathe. Cut excessive text. Check that measure (`--measure`) actually holds on long paragraphs, that the mono metadata layer is consistent in size and tracking everywhere it appears, and that heading scale steps are distinguishable rather than merely different.

## 3. Hero

The most important visual moment. Refine timing · spacing · typography · visual hierarchy · 3D object positioning · animation · scroll interaction · the transition into the personal intro.

It must communicate **KEATHAN NAIDOO** and the builder identity, and feel premium before a visitor understands anything else. **Add no UI.**

## 4. Opening

Must start quickly, feel intentional, never read as a loading screen, transition smoothly into the hero, work under reduced motion, and survive imperfect JS timing. **If it is already strong, leave it mostly intact** — adjust timing and choreography only where necessary.

## 5. The five worlds

Software · XR · AI/Data · Creative · Cybersecurity. Each must feel distinct while clearly belonging to one portfolio. Check colour, typography, visual density, atmosphere, transitions, project presentation, metadata, interaction.

**Avoid making any world look like a different website.** If one has drifted, pull it back toward the system.

## 6. The four transitions

`SOFTWARE → XR` interface/grid → spatial depth · `XR → AI/DATA` solid form → particles/data · `AI/DATA → CREATIVE` curves → typography · `CREATIVE → CYBERSECURITY` plates → network.

They must read as **subtle → build → transform → resolve**, not effect → effect → effect. Adjust timing where needed. Do not make them longer than they need to be. The transition supports the scroll; it must never interrupt it.

## 7. Scroll experience

Walk the whole journey looking for: abrupt jumps · excessive inertia · sections too slow or too fast · awkward pinning · sections that feel empty · transitions firing too early or too late.

Scroll should feel deliberate. **The whole site must not be in constant motion — some moments must breathe.**

## 8. Project presentation + media system

Extend the project system to support real content without a later redesign. A project supports: title · short description · discipline · role · technologies · image · video · **external link** · **repository link** · case study · **outcome** · **technical details**.

**Only render fields that actually exist.** No empty labels, no "N/A", no broken placeholders.

Media abstraction must handle: **IMAGE** (responsive, optimised) · **VIDEO** (short loop or project video) · **3D** (optional WebGL visual) · **GALLERY** (optional multiple images). A project with only an image must render perfectly.

**Images**: `next/image`, responsive `sizes`, appropriate quality, lazy loading, modern formats, meaningful alt text. Never load a large image to display it small.

**Video**: lazy load · poster images · no unnecessary autoplay · muted where autoplay is required · never load multiple large videos at once. Video is reserved for major visual moments only.

## 9. Content system

These must all live in editable data files, intuitively structured, with nothing hardcoded into presentation components: profile · disciplines · projects · skills · certifications · training · experience · links · current learning · current projects.

Make the shape obvious enough that Keathan can edit it without reading component code.

## 10. Skills Arsenal

**Keep the DOM/SVG architecture — do NOT convert to WebGL.** It is deliberately accessible and searchable.

Refine spacing · grouping · typography · hover behaviour · focus behaviour · selected state · discipline filtering/highlighting · mobile presentation. It must read as a visual *system*, not a skills list.

Selecting a skill reveals: name · discipline · category · short explanation · related technologies. Keep it fast and inline — **no large modal for simple skill information**.

## 11. Navigation + journey indicator

Keep it minimal. The indicator must update accurately, stay subtle, never obstruct content, work with keyboard, work on desktop. Hiding the rail on mobile is the current design and is correct.

## 12. Custom cursor

Keep it. Refine damping · hover state · typography · transition · click feedback. It must feel expensive, not gimmicky. Stays disabled on touch. It must never be required for interaction.

## 13. CV

Should feel like part of the digital experience, not a resume webpage. Contains profile · professional development · experience · certifications · training · timeline.

**No education section. No implied degree. No PDF download. Nothing invented.**

## 14. Currently building · Beyond the code · Hire Me · Footer

**Currently building** — compact, editable, communicates "I am still building". Unfinished work must never read as completed professional achievement.

**Beyond the code** — stays subtle. Reinforces engineering + visual creativity. Do not grow it into another discipline.

**Hire Me** — remains one of the strongest moments. `HAVE AN IDEA?` / `LET'S BUILD IT.` then `KEATHAN NAIDOO` / `keathan179@gmail.com` then professional links. Make the final scroll into it feel intentional. **No contact form.**

**Footer** — minimal, final frame of the experience. Links work, hover states work, typography intentional, nothing extra.

Document the strategy only: one exceptional cinematic asset each for HERO, XR, AI/DATA, CREATIVE, SECURITY — and additional transition media **only** if the existing WebGL transitions genuinely need it. No decorative assets.

## 16. Audits

**Accessibility** — semantic HTML · heading hierarchy · keyboard navigation · focus states · skip link · dialog behaviour · Escape handling · focus restoration · reduced motion · screen-reader labels · link semantics · image alt text · touch target size. The site must remain fully usable **without** the custom cursor, **without** WebGL, and **without** smooth scrolling.

**Mobile** — test at **375px, 390px and 430px**. Verify no horizontal overflow · readable typography · touch targets · navigation · project rails · transitions · skills · CV · Hire Me · footer. Mobile stays visually premium while intentionally simplifying desktop complexity.

**Performance** — verify no unnecessary React renders · no duplicate RAF · WebGL scenes pause when inactive · assets lazy load · videos do not preload unnecessarily · quality tiers work · resources dispose · no memory leaks · no console errors. **Measure before optimising. Do not optimise blindly.**
